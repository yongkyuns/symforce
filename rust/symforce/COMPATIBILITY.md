# Generated IMU storage API compatibility

The current runtime exposes generated update and roll-forward functions through
`imu::generated::<module>::sym::<function>`. Their optional geometry outputs are raw
storage matrices. Fresh generic generation instead writes typed `Rot3` and `Pose3`
values. Replacing those public signatures would break callers.

## Candidate boundary

`test/symforce_rust_geometry_codegen_test_data/imu_storage_adapters.rs` implements
candidate compatibility adapters against the fresh generic kernels. It contains no
numerical expressions: all matrix outputs are forwarded directly, while the requested
rotation or pose is written through a small typed temporary and copied back in storage
order. Absent outputs remain absent; the caller's prior buffer contents are not read.
Neither input nor output quaternions are normalized. The adapters retain the original
`Float + MatrixScalar + ReductionScalar` bound rather than requiring `Real`.

These adapters currently belong to the qualification fixture, not the production
runtime. No checked-in production kernel or high-level runtime call site is replaced.
The module alias binds to the canonical package generated by the real CLI; no freshly
generated expression file is rewritten to make an adapter compile.

## Frozen pre-migration reference

Comparing a fresh adapter only with the moving production runtime would become circular
when production starts calling the same fresh kernels. The storage contract instead
uses two frozen, test-only numerical kernels under
`test/symforce_rust_geometry_codegen_test_data/legacy_imu`. These are byte-for-byte copies
of `rust/symforce/src/imu/generated` at source commit
`f8a9aa72adf25bd375537d422c2ce2c77f5cc1bf`, retained by their original Git blob identities:

| Frozen file | Original Git blob |
| --- | --- |
| `imu_manifold_preintegration_update.rs` | `50687437ce79901b61f0cc4da0761babd3efbc3e` |
| `roll_forward_state.rs` | `d3670f7e1a6dac08710b20fda8e26639fd6c748f` |

The Python harness pins these identities, checks the exact two-file inventory and
regular-file requirement, and verifies both the fixture and its copied bytes before
compilation. It does not read the moving production source to obtain its reference,
regenerate the snapshot, or rewrite any frozen expression. Two lightweight Python
contracts check the valid snapshot and reject changed, missing, extra, or nonregular
entries. The legacy module scaffold is assembled separately from the frozen files.

The generated qualification library aliases its existing geometry dependency as
`symforce_rust`, preserving the old source's crate spelling without duplicating a
geometry implementation or adding a dependency. Both the live public API and the fresh
adapter are compared with the frozen all-output reference. Function-pointer assignments
check matching generic signatures for all three implementations from an external crate.

This freezes the two numerical kernels, not the entire geometry library or navigation
runtime. Types and test-input construction still use the geometry dependency. The
independent C++ qualification and autodiff reference remain necessary; this snapshot is
not a replacement for them. It also does not freeze or independently qualify the three
factor kernels or every high-level runtime operation. Do not refresh the snapshot to
make a future migration pass.

## Required executable contract

The existing geometry suite compiles the adapters and frozen kernels into its generated
`no_std` library and calls them from a separate Cargo integration-test crate.
For each of f32 and f64 the integration tests cover:

- All 512 combinations of the update's nine optional outputs, comparing frozen subset,
  live runtime, and adapter calls with an all-output frozen evaluation. Buffers start
  dirty; unrequested buffers must remain unchanged. Covariance comparisons use only
  the defined lower triangle; all five bias-derivative blocks are checked completely.
- All four roll-forward output combinations, including empty and partially requested
  outputs, with nonzero translation, velocity, gravity, and preintegrated state.
- Zero, non-unit, and sign-reversed quaternion storage controls on both the live runtime
  and adapter. These check storage behavior, not physically valid derivative models.
  A NaN-filled rotation output must be fully overwritten. Translation is compared
  independently of quaternion norm.
- Negative controls for numerical corruption, nonfinite output, and writes to an
  unrequested buffer. An additional shared-error control makes the live and adapter
  rotation outputs agree on an injected error, then requires the frozen reference to
  reject both. Agreement between the two moving implementations is not sufficient.

The suite retains its 108 existing library contracts and has ten external integration
tests. `cargo test --all-targets` executes both; the existing bare-metal library check
also compiles the adapters and frozen kernels. The integration tests execute on the
host, not an MCU. These counts describe the configured suite, not a passing result for
a new source head until its compiler logs have been inspected.
Epsilon values and component budgets come from the unchanged scalar contract table.
The existing strict Python runner requires execution, and the generated integration
source, frozen source, and Cargo logs are retained in the numerical qualification artifact.

## Remaining migration

After exact-head qualification, move the adapters to the public compatibility surface,
keep canonical typed kernels private and reproducible, and migrate both concrete f64
and scalar-generic internal consumers. The handwritten production derivative choice,
public runtime API, raw-storage semantics, numerical budgets, and performance gates
must remain intact. This fixture alone does not establish completed runtime migration,
replacement-kernel performance, or compatibility outside the exercised interfaces.
